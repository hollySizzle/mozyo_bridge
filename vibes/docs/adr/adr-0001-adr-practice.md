# ADR-0001: owner 決定は ADR として記録し、レビューは黙って上書きできない

- status: active
- date: 2026-08-16
- related: Redmine #15536 (導入 US)、#12580 / #15202 (動機となった実害)

## 決定 (規約行)

owner の意思決定は `vibes/docs/adr/` に ADR として記録し、最重要文書として扱う。active な ADR と
矛盾する review finding・実装変更は、その ADR を名指しした上で owner の明示承認を得ない限り採用
しない。

## 背景

owner が繰り返し指示した送信リトライ方針が、個々には筋の通った安全側レビュー指摘の積み重ねで
段階的に無効化された (#12580 → #15202 の経緯)。各レビューは正しく仕事をしたが、owner の優先
順位を参照する工程がどこにも無く、「決定はあったのに、誰もそれと突き合わせなかった」状態が
生まれた。決定の置き場と、レビューがそれを参照する義務をセットで導入する。

## 根拠 (逐語引用)

- 2026-08-16 owner (chat):「ユーザーの決定事項はアーキテクトディシジョンレコードかな、ADRを
  作った方がいいんじゃないかっていう説が今出てきているかな。…まずはドキュメントに書いていく
  べきで、それを何よりも重要なものとして扱うっていう方がいいかなって思う」
- 2026-08-16 owner (chat):「その提案を承認する。まずはこのシンプルなドキュメントレベルで管理
  していき、…うまくいきそうだったら、より他の場所にもそれを広げていこう」
- 2026-08-16 owner (chat、実害の認識):「そのエンターを押すっていうのは、もう何回も何回も何回も
  私が伝えたりして、でもそのためにレビューで骨抜きにされてたってことみたい」

## 影響

- reviewer (Codex auditor): review finding を出す前に、対象領域の active ADR を確認する。矛盾する
  指摘を出す場合は ADR を名指しし、「ADR 変更の提案」として書く。owner 承認なしにその指摘を
  required_correction として採用してはならない。
- implementer (Claude): ADR と矛盾する実装・修正を、レビュー指摘への対応であっても行わない。
  矛盾に気づいたら owner へ escalate する。
- 適用範囲: 本 repo (repo-local 宣言)。中央 preset / OSS 配布物は変更しない。他 repo への展開は
  運用実績を見て owner が判断する。
