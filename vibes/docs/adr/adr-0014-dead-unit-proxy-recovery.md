## 決定 (規約行)

実装を担っていたユニットが仕事の途中で死んで自分で終端報告できないとき、**その drain を担う一個上の上位層** (3階層ではプロジェクトコーディネーター、1階層/2役割では相方役) が本人の代理で実状態を回収し durable record に起こす。その際 **「事実」は回収するが「完了」は推測しない** — 権威証拠 (レビュー記録 + 本体への取り込み) が完了を示すときだけ抜けた最終更新を代理で埋め、無ければ「未完・要引き継ぎ」の事実を正確に記録する。**改修せず手で消して残骸を隠すことを禁じる**。

## 背景

ドレイン機構がユニットの local 記録だけを真実源にしていたため、実装完走・本体取り込み済み・Redmine close 済みでも、local 記録が壊れると「まだ終わっていない扱い」で fail-closed し、畳めない残骸として滞留した (#15842 / #15843、診断 #15693 j#109971)。安全に止まること自体は正しいが、上位の権威 (Redmine の完了・git の取り込み) で確かめ直す道が無く、結果として owner が最悪と定める「畳み残し」と「人間が janitor をやらされる」を機構自身が生んでいた。担い手は特定の役割名ではなく、その構造で drain を担う上位層である。

## 影響

- **担い手 (構造依存)**: 死んだユニットの drain を担う上位層。3階層 = プロジェクトコーディネーター (ADR-0011)、1階層/2役割 = 相方役 (ADR-0009)。役割名でなく「その構造の上位層」で拘束する。
- **鉄則**: 上位層は事実を回収して記録し、完了を推測しない。「コミットがある」≠「終わった」。上位が完了を裁定して未完成を空印鑑で通すことを禁じる (ADR-0011「上位は correctness を再監査しない」の対称)。
- **3ケース** (分かれ目 = レビュー + 取り込みという権威証拠の有無):
  1. 報告も完了も済み後片付けだけ残る → 権威証拠で確認し終端まで安全に畳む (pane 撤去込み。撤去前に当該 pane に未保存作業が無いことを検証する)。
  2. レビュー + 取り込み済みだが最終ステータス更新のみ抜け → 抜けた更新だけ代理で埋める。
  3. 途中死・コミットあり・未レビュー / 未取り込み → 完了扱い禁止。事実を記録し再ディスパッチ / レビュー / escalate。
- **起票の範囲**: ケース1・2 は元 issue の journal に追記し新規チケットを作らない (死んだレーンごとの新規チケット乱造を避ける)。ケース3 のみ新規作業項目を起票する。
- **fail-closed 維持**: 権威証拠が曖昧なら畳まず escalate (逆方向の誤削除防止)。破壊的自律の範囲そのものは owner escalate 対象 (#15844 と整合)。
- 適用範囲: 本 repo (repo-local 宣言)。実装は #15854。中央 preset / OSS 配布物は本 ADR で変更しない。
