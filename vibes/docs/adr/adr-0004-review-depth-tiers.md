# ADR-0004: レビュー深度は変更クラスで段階化し、途中再分類できる

- status: active
- date: 2026-08-16
- related: Redmine #15547 (導入 US)、#15536 j#106357 (owner 決定の逐語 anchor)、ADR-0003 (US 単位レビュー)

## 決定 (規約行)

レビューの深さは変更クラスに比例させる。動作を変えない**軽量クラス**の変更は 1 往復契約
(壊れる級の欠陥のみ差し戻し可、中小指摘は承認+メモ) とする。分類は検証される主張であり、
格上げは実装者単独でいつでも無コスト、格下げは承認必須。central preset の
`us_level_audit.task_level例外` の高リスク種別は軽量クラスに入れない。

## 背景

2026-08-16 の実測で、文書の書き間違い修正 (修正 10 分) にフル審査往復 (30-40 分) がかかる
事例が続き、owner が「軽量な変更でもレビューがやりあっている」ことを問題と認めた。同時に、
「ワンタスクだと思ったら膨らむ」のは常態であり、事前見積もりではなく途中再分類で対応する
方針を決定した。自己申告だけでは沈没コストと逆インセンティブで発動不足になるため
(#15531 で実例)、機械照合と自動格上げトリガーを併置する。

## 根拠 (逐語引用)

- #15536 j#106357 (owner 決定の逐語記録、2026-08-16): 「まあそうだね。ただしさ、実際のところ
  ちょっとしたワンタスクだと思ったけど、実はやってみたらめちゃくちゃ時間かかったとか、
  よくある話だよね。…途中で変更できるようにするべきだと思うんだよね。つまり、LM自体は
  これは長くなりそうだな、っていうことで変えるみたいなことをやった方がいいと思うんだけど」
- #15536 j#106357 (同、設計骨子への承認): 実装者が段階化・機械照合・非対称再分類・切り出し
  規則・#14796 優先度引き上げを提案した後、「OK、じゃあそうしよう。」

## 影響

- **軽量クラス** (閉じたリスト、`vibes/docs/rules/agent-workflow.md` の `review_depth_tiers` が
  正本): 文書の誤記・清書、テストのみの変更、コメント、生成物の再生成。reviewer は
  High/blocker 級 (壊れる・契約と矛盾する・安全境界に触れる) のみを差し戻し理由にでき、
  それ未満の指摘は「承認+メモ」で通し、メモは後続タスクとして起票する。
- **標準クラス**: 上記以外すべて。従来どおりの深度。`us_level_audit.task_level例外` の
  高リスク種別 (guardrail / release・CI / credential・権限 / destructive・migration /
  architecture・互換性) は宣言にかかわらず常に標準クラス。
- **分類は検証される主張**: レビュー依頼の diff が主張クラスと矛盾する場合 (軽量主張なのに
  src の動作コードや高リスクパスに触れている等)、reviewer は照合により自動格上げする。
- **途中再分類 (非対称)**: 格上げ (軽量→標準) は実装者単独・journal 1 行でいつでも可、
  ペナルティなし。格下げ (標準→軽量) は reviewer または owner の承認を要する。軽量案件が
  レビュー 2 周目に入った時点で自動的に標準クラスへ格上げされる (2 周目が要ること自体が
  軽量でなかった証拠)。
- **膨張と派生の区別**: 同じ成果物が大きくなっただけなら格上げして続行。作業中に別の
  成果物 (新しい欠陥・別機能) が生えたら、その場で別 issue に切り出して anchor を残す。
- 本 ADR は ADR-0003 (レビューは US 単位) の内側で深度を定めるものであり、レビュー単位を
  変えない。ADR-0002 と同様、本 ADR と矛盾する「深度を一律に戻す」変更は
  `adr_conflict_gate` の対象。
